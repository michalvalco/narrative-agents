## CRITICAL SCOPE CORRECTION (read before citing)

The acquisition task described this paper as "NVIDIA's AVO agent that reached 100 RHAE on ARC-AGI-3, August 2026." **That description conflates two distinct sources.**

- **This arXiv paper (March 2026) is about autonomous GPU-kernel optimization** (attention kernels on Blackwell B200 GPUs via evolutionary search). It contains **zero occurrences** of the strings "ARC", "ARC-AGI", "RHAE", "6,624", "public set", "private", or "Limitations" (verified by programmatic search over all 12 pages of the PDF, 2026-08-26).
- **The ARC-AGI-3 / 100.00 RHAE / 6,624-actions claims appear only in the NVIDIA developer blog post of 21 August 2026** (see companion source document `Sources\AVO_NVIDIA_blog_2026-08.md`). That blog post links back to this arXiv paper as the AVO architecture reference; as of 2026-08-26 no arXiv publication documenting the ARC-AGI-3 result itself was found.

Any claim attributing ARC-AGI-3 results to "the AVO paper" is therefore **UNVERIFIABLE against this paper** and must be cited to the blog post instead.

### (a) Architecture components — main loop, persistent memory, supervisor

- **EXPLICIT (p. 1, Abstract):** "Rather than confining a language model to candidate generation within a prescribed pipeline, AVO instantiates variation as a self-directed agent loop that can consult the current lineage, a domain-specific knowledge base, and execution feedback to propose, repair, critique, and verify implementation edits."
- **EXPLICIT (p. 5, §3.2 "Anatomy of a Variation Step"):** "A single variation step in AVO, producing xt+1 from the current lineage Pt, is an autonomous agent loop. The agent is a general-purpose coding agent with planning, tool use, and persistent memory (details in Section 4), and a single step may involve numerous internal actions."
- **EXPLICIT (p. 5, §4.1 "Setup — Agent"):** "It maintains persistent memory through its conversation history, which accumulates the full context of prior edits, compiler outputs, profiling results, and reasoning across the evolutionary process."
- **EXPLICIT (p. 5, §3.3 "Continuous Evolution") — the supervision mechanism:** "In long-running autonomous optimization, two failure modes can impede progress: the agent may stall when it exhausts its current line of exploration, or it may enter unproductive cycles of edits that repeatedly fail to improve scores. To mitigate both, AVO incorporates a self-supervision mechanism that detects these scenarios and intervenes. Once triggered, the mechanism reviews the overall evolutionary trajectory and steers the search toward several candidate optimization directions."
- **EXPLICIT (p. 5, §3.3) — main agent vs. supervisor:** "Throughout this process, the main agent autonomously decided when to attempt new optimizations, when to revisit earlier approaches in Pt, and when to shift strategy, while the supervisor maintained forward progress by intervening during periods of stagnation."
- **EXPLICIT (p. 4, Figure 2 labels):** the architecture figure contains the labeled boxes "AVO Main Agent Loop", "Monitor Stagnation", "Conditional Intervention", and "AVO Supervisor Agent" (figure text; layout garbled by extraction, labels verified in PDF text).
- **STRONG INFERENCE:** The paper's terms for the three components are "autonomous agent loop" / "main agent", "persistent memory" (implemented as accumulated conversation history), and "self-supervision mechanism" / "supervisor". The word "harness" does not appear in the paper; it is blog-post vocabulary.
